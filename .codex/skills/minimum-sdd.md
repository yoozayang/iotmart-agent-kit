# Minimum SDD

Before implementation or a design change:
- Read the supplied WI/spec, affected source, and routed system context.
- State: change summary, affected files/systems, expected behavior, validation, open questions/risks.
- Separate confirmed scope from unresolved decisions; do not implement unresolved choices.

When recording the SDD, use `SDD（草稿）` or `SDD（定案：YYYY-MM-DD）`.
Use a table with `項目 | 做法 | 位置`, one sentence per change.
Keep implementation constants and 3–5 checkable acceptance outcomes below the table.
Put evidence and dated decisions in technical notes or discussion updates. Keep open choices under pending decisions.
